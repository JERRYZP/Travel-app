# 云开发数据库索引清单

> 2026-08-30 与 `cloudfunctions/notifier` 时间窗分页扫描同步整理。
> **部署顺序提醒**：先在本页建完「必须」索引，再重新部署 `notifier` 云函数，否则 `notifier` 新的 `where + orderBy('releaseAt')` 查询会因缺索引直接报错。

## 必须（本次改动依赖，云开发控制台 → 数据库 → 对应集合 → 索引 → 新建）

| 集合 | 索引字段（按顺序） | 服务对象 |
| --- | --- | --- |
| `reminder_tasks` | `backendStatus` + `releaseAt` | notifier 时间窗扫描、sweepMissed 判 MISSED（`where` 等值 + `orderBy('releaseAt')`） |
| `reminder_tasks` | `userId` + `tripId` | `task.list(tripId)`、`task.clear(tripId)`、级联删除计数 |
| `reminder_cart` | `userId` + `tripId` | `cart.list(tripId)`、`cart.clear(tripId)` |
| `trips` | `userId` | `trip.list`、`trip.createOrMerge` 查已存在行程 |

## 建议（数据量涨到几千条后再建，避免全表扫）

| 集合 | 索引字段（按顺序） | 服务对象 |
| --- | --- | --- |
| `reminder_tasks` | `userId` | `task.list` 不带行程筛选、`task.clear` 全量 |
| `reminder_tasks` | `userId` + `tripId` + `backendStatus` + `releaseAt` | `trip.list` 取每个行程最近提醒（`where` + `orderBy('releaseAt').limit(1)`） |
| `users` | `openId` | `user.profile` / `updateNotifyPrefs` / `updateUserProfile` / `addSubscribe` / `getSubscribe` |
| `search_history` | `userId` | `spots.searchHistory` |
| `feedbacks` | `userId` | `feedback.list` |

## 说明

- 云开发数据库索引为「等值 + 排序」复合索引：字段顺序要严格按上面列出，单字段也要加上（例如 `reminder_tasks` 同时需要 `userId` 单字段与 `userId + tripId` 复合，二者用途不同，都要建）。
- `backendStatus + releaseAt` 用升序即可覆盖 `releaseAt` 的范围/排序查询。
- 建完索引后，`reminder_tasks` 集合总量仍很小时（几百条内）不必急着建全部；4 个「必须」项请先建，因为 `notifier` 部署后即依赖。
