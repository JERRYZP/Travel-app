## 二、结论与交付范围

当前产品必须同时完成三层配置，缺一不可：

1. **平台侧**：在微信小程序管理后台完善《小程序用户隐私保护指引》。平台会按实际调用的隐私接口校验声明，首页代码中的 `<button open-type="chooseAvatar">` 和 `<input type="nickname">` 属于必填项。
2. **应用内文本**：提供可独立访问、可滚动阅读的《隐私政策》和《用户服务协议》。隐私页面应提供打开微信侧《小程序用户隐私保护指引》的入口。
3. **入口与运行验证**：在“我的”页提供清晰入口，真机验证同意、拒绝、撤回和接口调用表现。提审版本的隐私指引必须与当前代码实际处理的信息一致。

当前基础库为 `3.17.1`，高于微信隐私能力启用门槛 2.32.3，不需要依赖 `__usePrivacyCheck__` 才启用隐私检查。微信官方弹窗会在隐私接口触发且用户尚未同意时展示；本项目使用官方弹窗作为主流程，补充应用内页面和入口，不另造一套“同意后才启动小程序”的阻断弹窗。

## 三、当前数据处理事实

| 信息/能力 | 当前实现 | 是否涉及微信隐私接口 | 协议处理 |
|---|---|---|---|
| OpenID | 云函数从微信上下文取得，用于用户隔离 | 平台服务侧身份能力 | 已写入《隐私政策》 |
| 昵称 | 系统可生成；用户可用 `input type="nickname"` 填入或自行输入 | 是 | 平台必须声明“收集你的昵称、头像” |
| 头像 | 系统默认图；用户可用 `open-type="chooseAvatar"` 选择并上传云存储 | 是 | 平台必须声明“收集你的昵称、头像” |
| 手机号 | 用户编辑资料时主动填写，选填；无 `getPhoneNumber` | 否 | 已写明“不读取微信绑定手机号” |
| 行程/日期/提醒 | 云数据库按 OpenID 隔离 | 否 | 已写明用途和保存规则 |
| 搜索历史 | 云数据库保存关键词，最多 10 条，可清空 | 否 | 已写明用途和清理方式 |
| 订阅消息额度/发送状态 | 一次授权一条，云端记录模板、额度和错误状态 | 订阅消息授权 | 已写明授权、拒绝和送达风险 |
| 反馈/纠错/联系人 | 用户主动提交，联系方式选填 | 否 | 已写明用途和最少化要求 |
| 分享分析 | `wx.reportEvent`，仅公开入口/景点/动作，不含 OpenID、行程 | 微信自定义分析 | 已写明事件范围和本地区重 |
| 云开发日志 | `wx.cloud.init({ traceUser: true })`，用于故障与安全 | 云平台能力 | 已写明日志目的和保留原则 |
| 地理位置、相机、麦克风、通讯录、相册读取、日历、剪贴板 | 当前代码未调用 | 否 | 平台不勾选，协议明确“不主动收集” |
| 第三方广告或独立统计 SDK | 当前代码未接入 | 否 | 平台无需填报相关广告 SDK |

## 六、提审前必须确认

1. **联系邮箱可用**：当前文本使用仓库现有联系邮箱 `515207770@qq.com`。发布前必须确认它是实际可收件、可处理隐私请求的公开联系方式；如不适用，替换两份协议和平台填写内容。
2. **运营主体准确**：主体名称、注册地址、统一社会信用代码已回填，发布前与微信主体信息再次核对。
3. **发布时更新日期**：将“更新日期/生效日期”改为实际发布日。
4. **平台声明与代码一致**：后台勾选必须覆盖昵称、头像；未调用的位置、相机、通讯录、日历、相册读取等接口不要多勾。
5. **隐私弹窗真机验证**：删除小程序或清除授权状态后，首次触发头像/昵称功能，确认微信官方弹窗、协议名称、查看协议和拒绝路径均正常。

## 七、审核前验证步骤

1. 在开发者工具清除模拟器缓存和授权数据。
2. 打开小程序，进入“我的-编辑资料”，点击头像或昵称输入框，确认微信隐私授权弹窗出现。
3. 点击“查看隐私协议”，确认打开的微信侧指引名称正确、内容与当前版本一致。
4. 分别验证“同意”和“拒绝”：同意后头像/昵称能力可用；拒绝后界面给出可理解的失败提示，不卡死、不循环弹窗。
5. 在小程序“我的-隐私与协议”中确认两份协议均能直接打开、滚动到底部、返回正常。
6. 检查平台侧隐私指引、应用内隐私政策、用户服务协议、实际接口调用四者一致。
7. 执行：

```bash
npm run sync:legal
npm test
npm run check
git diff --check
```
